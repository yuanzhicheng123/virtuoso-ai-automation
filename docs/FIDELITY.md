# 能不能"一比一复现"？—— 分层判定 + 实测分数 + 成本

先给结论：**整体 1:1 不可能，也不需要**；但"1:1"可以拆成四层，其中三层能测、能逼近，
第四层（交互体验 / 规模 / 性能）不是算法问题，投人也换不来"一样"。

下面所有数字都是在这台机器上量出来的（IC2310 + tsmcN65），不是拍脑袋。

---

## 1. 先看对手有多大（实测）

| 维度 | Virtuoso IC2310 实测 | vlight 现状 | 倍率 |
|---|---|---|---|
| 安装体积 | **29 GB** | 0.3 MB（源码） | ~10⁵ |
| 文件数 | **262,626** | 40 | ~6.5×10³ |
| 可执行文件 | **435** | 1 个 Python 包 | — |
| SKILL 运行时上下文 | **221 个 `.cxt`** | 1 个解释器 | — |
| 真实 SKILL 脚本 | **3,519 个 `.il`** | 自带 1 个示例 | — |
| 脚本里出现的函数 | 813 个（其中 537 个是用户自己 `procedure` 的） | 内置 100+ | — |
| PDK 模型（单个文件） | **135,214 行 / 131 个 subckt**（另有 156 MB 的 28 nm 模型） | level-1 MOS 一个 | — |
| 数据库 | OpenAccess 二进制，版本绑定（oa_v22.61.003） | JSON + 文本 | — |

结论：**它不是"一个功能"，是三十年、上千人年的产品**。任何"1:1"的说法在工程上都站不住。

---

## 2. 把"1:1"拆成四层（这才是能讨论的东西）

| 层 | 含义 | 判据 | 现在 | 到 100% 的差距 |
|---|---|---|---|---|
| **L1 数据可交换** | 文件能互相读 | GDS/CDL/网表/PSF 字节级或语义级一致 | **≈95%** | OA 二进制不解析（靠 SKILL dump 桥） |
| **L2 脚本/API 兼容** | 老脚本能跑 | 同一段 SKILL/OCEAN 结果一致 | **调用覆盖 99.1%**（函数个数 26.8%） | 少量内置函数、`hi*` GUI 调用、SKILL++ |
| **L3 数值等价** | 同一输入同一结果 | 与解析解/ Spectre 的误差在容差内 | **在支持的器件/分析内 100%** | 出了子集就是 0：BSIM4、PSS/HB、pnoise… |
| **L4 交互/规模/性能** | 用起来一样 | GUI、10⁷ 器件、多线程、内存 | **0%** | 不是算法问题，是产品工程 |

**所以"一比一"= 四层都 100%，这是不可能的；"功能等价"= L1–L3 在目标子集内 100%，这是可以验收的。**

---

## 3. L3 的实测：一致性套件（`conformance/`）

21 个用例，每轴都有参考值（解析解或 Spectre）：

```
总体 21/21 = 100%
simulation   8/8   RC/二极管/噪声/反相器/环振 + vs Spectre
netlist      2/2   真实 VCO 往返、subckt→设计
layout       3/3   GDS 往返（KLayout 校验）、布尔、提取 R
verification 4/4   LVS 改名匹配、错连检出、DRC、短路
automation   3/3   SKILL 建图、OCEAN 扫描、真实 ADE 状态
data         1/1   CDF 缺省值补齐
```

具体误差（都在套件里可复跑）：

| 用例 | 参考 | 实测偏差 |
|---|---|---|
| RC 直流 | 2.000000 V | < 1e-9 |
| RC 幅频/相位 | 解析式 | 1.1e-16 / — |
| RC 阶跃 | 1−e^(−t/τ) | 9.2e-4 V |
| 二极管 Vd | 二分法 | 2.2e-16 V |
| RC 噪声积分 | kT/C | 0.06% |
| 自研 vs Spectre | 同网络 AC | <2% 幅频、<0.02 rad 相位 |

**注意**：这些"100%"只对**我们支持的器件与分析**成立（R/C/L/V/I/E/G/D/level-1 MOS；DC/AC/TRAN/噪声）。
换成 BSIM4 + PSS + 失配模型，分数立刻掉到 0——这不是实现质量问题，是覆盖边界。

## 4. 各层"到 100%"具体要做什么、要多久

| 缺口 | 影响 | 工作量（人月） | 备注 |
|---|---|---|---|
| BSIM4/PSP 模型卡 + 温度/失配/噪声 | L3：PDK 器件才能对 | 2–3 | 公式公开，参数从 PDK 读 |
| 稀疏 LU + 预条件迭代 | L4：规模从 10³ → 10⁶ | 1–2 | 否则大电路内存爆 |
| PSS/shooting + pnoise | L3：VCO/PA 流程 | 3–4 | 现有环振只能靠 TRAN |
| 版图器件识别 + 真 LVS | L3：版图对原理图 | 3–5 | 现在 LVS 是网表对网表 |
| 3D 场求解 / 模型降阶 | L3：提取精度 | 6–12 | 现在解析 + 2D FD |
| Calibre 级 DRC 引擎 | L2：规则语言兼容 | 12+ | 规则集本身是厂商数据 |
| Web/Qt GUI（可编辑） | L4 | 6–10 | 现在的 SVG/HTML 只读 |
| OA 二进制读写 | L1 | 6–12 | 格式未公开，建议继续走 SKILL 桥 |
| 数字/混合信号（AMS、Verilog） | 范围外 | 24+ | 另一条产品线 |

**做到"RFIC 手工设计闭环可用"（不含 GUI/大规模/数字）：约 24–36 人月。**
**做到"1:1"：没有这个终点**——即使投入 200 人年，也拿不到 bit-exact：
浮点求和顺序、Newton 迭代路径、模型版本、工艺角数据都不一样，而且 GUI 体验没有客观判据。

---

## 5. 可验收的替代定义（建议写进验收标准）

> **接口兼容 + 数值等价（带容差）+ 数据可交换 + 流程可复现**

四条都能测：

1. **接口兼容**：拿真实脚本语料跑，统计"调用覆盖率"——现在 **99.1%**（352,909 次内置调用里覆盖 349,7xx 次）；函数个数 74/276。
2. **数值等价**：每个分析给容差表（DC 1e-6 相对、AC 1e-3、TRAN 1e-3、噪声 2%），对同一激励与 Spectre 比；现在全部达标。
3. **数据可交换**：GDS 往返（KLayout 读回 58/58 图形）、CDL/网表往返、PSF 解析；OA 走 SKILL dump。
4. **流程可复现**：从 SKILL 建图 → 网表 → 仿真 → 版图 → 提取 → 后仿 → LVS/DRC 全链路一条命令跑完（`docs/FLOW`）。

---

## 6. 继续提高分数的性价比排序

1. **BSIM4 卡**（+15% 数值覆盖，PDK 器件直接可仿）
2. **稀疏求解**（规模 ×100，代价 1–2 人月）
3. **版图器件识别**（LVS 才真正对得上版图）
4. **PSS/pnoise**（VCO/PA 的相位噪声流程）
5. **提取升级**（3D 场 + 降阶）
6. **GUI**（Web canvas，先只读再可编辑）
7. **OA 读取**（继续用 headless SKILL 导，或逆向格式）

按这个顺序，每加一项，`conformance` 就多几条用例、分数可量化地往上走——
**"复现"就从一句口号，变成一条可测量的收敛曲线。**
